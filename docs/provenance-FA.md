# خط مبنای کنترل‌ها و منشأ آن‌ها

[English](provenance.md)

فهرست ۱۴۵ کنترل و نام ۱۰۷ Playbook از کتابچه انگلیسی **Defense-in-Depth Software Security Engineering / 2026** ارائه‌شده توسط کاربر (۴۴ صفحه، مورخ ۱۵ نوامبر ۲۰۲۶) گرفته شده‌اند. این مخزن آن مرجع مهندسی را به Workflow قابل‌استفاده مجدد Claude Code تبدیل می‌کند. خود کتابچه در اینجا بسته‌بندی نشده و **ادعا نمی‌شود که انتشار رسمی OWASP، NIST یا Anthropic است**.

چارچوب‌های منتخب مورد اشاره خط مبنا:

- [OWASP Top 10](https://owasp.org/www-project-top-ten/): آگاهی از ریسک، نه راستی‌آزمایی کامل.
- [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/): الزامات آزمون‌پذیر Web/API.
- [OWASP API Security](https://owasp.org/www-project-api-security/): BOLA، BOPLA، مصرف منابع و SSRF.
- [OWASP MASVS and MASTG](https://mas.owasp.org/): الزامات امنیت موبایل و رویکردهای تست.
- [NIST SP 800-63](https://pages.nist.gov/800-63-4/): راهنمای هویت دیجیتال.
- [NIST SSDF](https://csrc.nist.gov/projects/ssdf): رویه‌های توسعه نرم‌افزار.
- [SLSA](https://slsa.dev/): سطوح و رویه‌های یکپارچگی زنجیره تأمین.

برای قوانین جاری، آخرین نسخه معتبر هر استاندارد را بررسی کنید؛ این کاتالوگ ثابت یک **خط مبنای تاریخ‌دار** است و نسخه‌های آتی را خودکار به ارث نمی‌برد. نام‌های OWASP/NIST مرجع هستند؛ کاتالوگ گردآوری‌شده گواهی انطباق استاندارد نیست.

## تفسیر اولویت و دشواری

- `P0`: خط مبنای حیاتی امنیت برای Workflow عمومی یا ارزشمند.
- `P1`: بهبود در چرخه بعدی.
- `P2`: وابسته به بلوغ و مدل تهدید.
- `difficulty_pct`: تخمین نسبی متخصص برای تیم باتجربه در محیط نماینده؛ نه کاهش ریسک اندازه‌گیری‌شده.
- `ease_pct`: `100 - difficulty_pct`؛ نه احتمال موفقیت یا میزان حفاظت.

## محدودیت پوشش خودکار

Scanner مجموعه محدودی از الگوهای آفلاین را فقط برای بخشی از شناسه‌های کنترل دارد. Agent باید تمام کنترل‌های **قابل‌اعمال** را با کد واقعی و سایر شواهد مجاز انتخاب و بررسی کند. `NOT_APPLICABLE`، `NEEDS_REVIEW` و `OUT_OF_SCOPE` بر PASS ساختگی ترجیح دارند.
