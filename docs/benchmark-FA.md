# خط مبنای Benchmark مصنوعی نشانه‌ها

اولویت P0 · #78 · RFC #37 · [English](benchmark.md)

از Checkout مخزن اجرا کنید:

```bash
python3 scripts/benchmark_scanner.py
```

Manifest مصنوعی با مجوز MIT برای هر یک از ۱۷ شناسه Rule بسته‌های محدوده‌دار یک نمونه مثبت و منفی دارد. مثبت نشان‌دهنده Candidate مورد انتظار برای بازبینی است، نه آسیب‌پذیری تأییدشده. منفی یعنی نبود همان Candidate خاص، نه امنیت برنامه. هر نمونه مؤلفه منتخب موقت و یک مؤلفه هم‌سطح حذف‌شده با نشانه مثبت ایجاد می‌کند. کد Fixture اجرا نمی‌شود، شبکه یا داده خصوصی مشتری استفاده نمی‌شود و فایل‌های موقت حذف می‌شوند.

گزارش TP/FP/TN/FN، دقت Precision = TP/(TP+FP)، Recall = TP/(TP+FN)، FPR = FP/(FP+TN)، FNR = FN/(FN+TP) را با مخرج صریح و null برای نسبت تعریف‌نشده ارائه می‌کند. معیارها بر اساس فریم‌ورک و Rule گروه‌بندی می‌شوند؛ هر نمونه فقط Rule تعیین‌شده را امتیازدهی و شناسه سایر Candidateها را جدا گزارش می‌کند. این مجموعه کوچک و انتخاب‌شده نماینده پروژه واقعی نیست. Manifest، هش اسکنر، Commit، نسخه Python و زمان اجرای اسکنر مشخصات اجرا هستند. زمان اجرا معادل زمان رسیدن به اولین یافته قابل اقدام نیست.

CI این Benchmark را در هر Job ماتریس Python اجرا می‌کند. جفت ناقص یا نامعتبر، اسکن ناقص، نگاشت اشتباه یا نشت محدوده باعث شکست Job می‌شود؛ دقت اندازه‌گیری‌شده بدون آستانه دلخواه گزارش می‌شود. نتیجه واقعی را در Logهای CI ببینید. ارزیابی Agent، تشخیص معنایی آسیب‌پذیری، اصلاح تأییدشده، بهره‌برداری واقعی یا تأیید نسخه فریم‌ورک ادعا نمی‌شود. مراحل بعدی نیازمند Fixture واقع‌گرایانه با برچسب مستقل، آستانه انتشار، ارزیابی Runtime و Agent با مجوز هستند. برای بازگردانی PR را Revert کنید؛ رفتار Runtime تغییر نکرده است.
