# روش مشارکت در کنترل یا Playbook تخصصی

خط مبنا عمداً به منبع ثابت سال ۲۰۲۶ قابل ردیابی است. افزودن‌ها باید توسعه صریح باشند، نه بازتعریف پنهانی ۱۴۵ شناسه کنترل.

۱. تهدید، Stack هدف، مرز اعتماد، معیار پذیرش و استاندارد منبع مرتبط را مشخص کنید.
۲. بررسی کنید شناسه کنترل و Playbook موجود آن را پوشش می‌دهند یا نه.
۳. برای بهبود راهنمای موجود، فایل مرجع `plugins/security-guardian/skills/security-guardian/references/playbooks/<slug>.md` را ویرایش کنید.
۴. برای پیشنهاد کنترل واقعاً جدید، دلیل تغییر خط مبنا را بیان کنید و شمارش کاتالوگ و تست‌ها را عمداً تغییر دهید؛ شمارش نادرست `145` را حفظ نکنید.
۵. Payload واقعی بهره‌برداری زنده و اسرار منتشر نکنید. Fixture تست محلی پالایش‌شده و نتایج **منفی** مورد انتظار از کد ایمن ارائه دهید.
۶. اصلاح متناسب و قابل بازگردانی باشد. ریسک قرارداد API، مهاجرت داده، کارایی و سازگاری عقب‌رو را مشخص کنید.
۷. `make validate test` را اجرا و False Positive/Negative مورد انتظار را مستند کنید.

Playbook خوب شامل کاربردپذیری، روش‌های کشف، مدل ریسک، تست پذیرش، اصلاح ایمن، مجوز انسانی لازم، انتظارات شواهد و مثال‌های موارد حل‌نشده است. نبود تطابق Regex مبنای تأیید نیست.
