# هدایت درخواست و محدوده فریم‌ورک

اولویت P0 · #76 · [English](intent-routing.md)

توضیح مرجع Skill اکنون بازبینی وب، API، موبایل و بسته‌های محدود فریم‌ورک را شامل می‌شود. کشف و فعال‌سازی واقعی Agent باید جداگانه آزموده شود. درخواست طبیعی توسط Agent تفسیر می‌شود، نه Parser عمومی متن. فرمان خاص صریح اولویت دارد؛ برای بازبینی روشن امنیتی حالت audit پیش‌فرض است. plan بدون ویرایش، fix نیازمند مجوز صریح، verify نیازمند شاهد و درخواست متعارض نیازمند رفع ابهام است. مجوز جدید اجرای تست، ارتباط با سامانه زنده یا تغییر تنظیمات محافظت‌شده استنباط نمی‌شود.

برای یک نام دقیق فریم‌ورک از `security_scan.py --root /path/to/project --discover --framework React` استفاده کنید. این پیش‌نمایش فقط خواندنی است، نه اسکن یا اجرای ممیزی. تنها مؤلفه یکتای تک‌نقشی با کشف کامل Manifest انتخاب می‌شود. نبود تطابق، چند تطابق، نقش مختلط، Manifest نامعتبر یا کشف بریده‌شده نیازمند انتخاب است. Containerهای Workspace حذف می‌شوند. ابزار پیش از بازگرداندن Profile سفارشی کشف را دوباره بررسی می‌کند؛ ریشه‌های منتخب و حذف‌شده را نمایش دهید و همان ریشه‌های مجاز را در tracker begin استفاده کنید. درخواست صریح نقش/مسیر همچنان از Resolver معمول استفاده می‌کند. درخواست صرفاً فریم‌ورک را خودکار به کل نقش گسترش ندهید.

تست مصنوعی محدوده دقیق، ابهام، نبود و اختلاط شواهد، Manifest نامعتبر و Containerهای Workspace را پوشش می‌دهد. این ابزار Sandbox، تأیید نسخه نصب‌شده یا اثبات فعال‌سازی Agent فروشنده نیست. برای بازگردانی PR مستقل را Revert کنید؛ تاریخچه و فرمان‌های مستقیم قبلی بدون تغییر هستند.
