# مدل امنیت و اعتماد

## کاربرد موردنظر

Security Guardian برای ممیزی دفاعی و اصلاح نرم‌افزارهایی است که **مالک آن هستید یا صریحاً مجاز به تست آن‌ها هستید**. اسکنر تست نفوذ زنده، پلتفرم افشای آسیب‌پذیری یا ایجنت اجرای کنترل تولید نیست.

## نمایه دسترسی

| مؤلفه | فایل پروژه | تاریخچه محلی | شبکه خارجی | عملیات تولید |
|---|---|---|---|---|
| اسکنر Python | سورس/تنظیمات واجد شرایط را می‌خواند | به‌خودی‌خود ندارد | ندارد | ندارد |
| Tracker Python | زیرمجموعه کوچک شامل فراداده Git را می‌خواند؛ شواهد را می‌نویسد | در `.security-guardian/` می‌نویسد | ندارد | ندارد |
| ایجنت Claude Code | تابع مجوز پلتفرم/کاربر | گزارش می‌نویسد و در `fix` ممکن است سورس را ویرایش کند | فقط از طریق ابزار جداگانه مجاز | نیازمند تأیید جداگانه کاربر |

## تهدیدهای قابل توجه

- **محتوای مخرب پروژه:** README/کامنت، فایل تولیدشده، فراداده وابستگی یا Payload ثبت‌شده می‌تواند Prompt Injection داشته باشد؛ آن را شاهد بدانید، نه اختیار بالاتر از قواعد ایمنی Skill.
- **اطمینان کاذب:** یک Regex اثبات بهره‌برداری نیست و نبود تطابق امنیت را اثبات نمی‌کند. کنترل نیازمند زیرساخت مستقر از Snapshot مخزن قابل گواهی نیست.
- **افزایش نامناسب سطح دسترسی با اصلاح:** بازطراحی وسیع احراز هویت، سیاست، OTP، PKI، پرداخت یا شبکه ممکن است دفاع را حذف یا قواعد ثابت کسب‌وکار را نقض کند؛ تست هدفمند، بازبینی و رضایت کاربر لازم است.
- **نشت گزارش حساس:** یافته، مسیر داخلی و وضعیت امنیت ممکن است در سورس عمومی، مخزن Artifact یا لاگ مشترک ایجنت افشا شود؛ پالایش و جداسازی کنید.
- **اثرات جانبی تست:** Fuzzing سرتاسری، اسکن شبکه، تست مخرب و Load Test می‌توانند سیستم را مختل کنند؛ Fixture محلی/Staging ایزوله، مجوز و بودجه نرخ محدود استفاده کنید.
- **زنجیره تأمین:** Playbook و اسکریپت مشارکت‌شده می‌تواند رفتار را تغییر دهد؛ PR را بازبینی، CI اجرا و Diff انتشار را پیش از ارتقا بررسی کنید.

## موارد بدون تضمین

- اسکنر همه تست‌های ASVS/MASVS/OWASP را به‌طور جامع پیاده‌سازی نمی‌کند.
- همه Zero-dayها، نقص منطق، Race Condition یا Bypassها را تشخیص نمی‌دهد.
- `VERIFIED_FIXED` از شواهد ارائه‌شده ثبت می‌شود؛ Tracker اصالت شواهد را مستقلاً اعتبارسنجی نمی‌کند.
- امنیت سیستم‌عامل میزبان، Reverse Proxy، KMS، زیرساخت امضا، تنظیم GitLab، Backup یا توپولوژی تولید بدون دسترسی و ارزیابی مجاز تکمیلی گواهی نمی‌شود.
- مصونیت Bug Bounty یا ریسک صفر تولید تضمین نمی‌شود.

## استفاده ایمن

۱. کار معتبر خود را جداگانه Backup/Commit و پیش از درخواست تغییر `git status` را بررسی کنید.
۲. با `audit` شروع و یافته‌ها را بخوانید؛ مرز اعتماد واقعی را تأیید کنید.
۳. P0 و اثر واقع‌بینانه بهره‌برداری را اولویت دهید، نه فقط درصدها.
۴. تغییر محدود `fix` و تست منفی مجاز را تأیید کنید.
۵. از `verify` استفاده و خروجی تست و یافته حل‌نشده را بازبینی کنید؛ برای سیستم با ارزش بالا ارزیابی مستقل ترتیب دهید.
۶. `.security-guardian/` را خصوصی نگه دارید.

## Adapter اختیاری تست محلی

[اجراکننده راستی‌آزمایی محلی](verification-runner.md) یک Adapter جداگانه Python unittest با مجوز صریح است. تست محلی قابل اعتماد را اجرا، فراداده محدود رسید را ثبت و اثرانگشت ورودی انتخاب‌شده قبل/بعد را بررسی می‌کند. کد تست می‌تواند اثر جانبی داشته باشد؛ Runner سندباکس یا تأییدکننده مستقل یافته نیست. Fixture تحت مالکیت ایزوله و بدون اعتبارنامه تولید استفاده کنید؛ تست غیرقابل اعتماد مخزن را خودکار اجرا نکنید.

فرمان صریح `run-test` در Tracker به Adapter محلی مورد اعتماد واگذار می‌شود؛ کد تست ممکن است اثر جانبی داشته باشد. رکورد دستی اجرای مستقل نیست و رسید محلی گواهی محسوب نمی‌شود. [شواهد Tracker](tracker-execution-evidence-FA.md).

در جدول مجوزها، سطر Tracker رفتار پیش‌فرض را توصیف می‌کند؛ `run-test` اجرای اختیاری کد تست قابل اعتماد است و دسترسی شبکه آن توسط Sandbox محدود نمی‌شود. اجرای تولید مجاز نیست.
